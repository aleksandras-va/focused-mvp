# Decisions

Settled choices. Do not relitigate them; if one blocks you, say so.

## Stack

- Postgres in Docker, host port 5434.
- Kysely as the query builder. Not Prisma, not Drizzle.
- `src/db/types.ts` is generated by kysely-codegen from the live database.
- No migration files. Schema changes are SQL run against the database.
- Layering: `db` → `repositories` → `services` → `app`.
- Components split into `ui/` (shadcn, vendored) and `features/<name>/`.
- No comments in code.
- Everything in English. Lithuanian later, as i18n.
- Money is integer EUR cents.
- Table names are singular: `model`, `brand`, `user`, `listing`. Constraints and indexes
  follow (`model_pkey`, `listing_seller_id_idx`). Kysely quotes identifiers, so the
  reserved word `user` is safe in code; raw psql needs `"user"`.
- The inclusion enum is `inclusion`, not `listing_inclusion` — a table and a type cannot
  share a name in Postgres.

## Catalog and search

- Sellers pick a curated model, they never type one.
- One name per model: `model.display_name`. No alias table.
- Search uses `word_similarity` against `model.normalized` (punctuation stripped,
  spaces kept) with a 0.3 floor, plus a prefix match. Use `word_similarity`, not
  `similarity` — the latter compares whole strings and fails on short forms like "xt3".
- Ties break on shorter name first, then newer model, so "r6" ranks the R6 above the
  R6 Mark II.
- Always show a list of matches. Never auto-pick a model for the user.
- Synonyms with no shared characters (`ILCE-7M3`, "nifty fifty") are not supported and
  are out of scope for MVP. When needed, add `models.search_terms text[]`.
- Semantic search (pgvector) is deferred. Poor at model codes; cannot separate X-T3
  from X-T30.
- Model uniqueness is `(brand, name, mount)` with NULLS NOT DISTINCT — third-party
  lenses share names across mounts.

## Specs

- Typed columns only for fields you filter on. JSONB and a spec-definitions table wait
  until a real spec source is imported.
- Nullable boolean means unknown; `false` means absent.

## Accounts

- Placeholder auth: no passwords, unknown email creates the account. Sessions are real —
  database-backed, httpOnly cookie, 30 days. Replace before real traffic.
- Seller type is chosen at signup. Store fields are all-or-nothing.

## Listings

- No title field. The canonical model name is the title.
- Condition splits into cosmetic and functional.
- Inclusions are an enum plus a join table, so they can become filters.
- `location`, not `city`.
- Shutter count is asked only for cameras.

## Photos

- Compress in the browser to WebP before upload. Large camera files must never pass
  through the Next server.
- Two sizes per photo: 2560px long edge for the listing page, 800px for grid cards.
- Accept JPEG, PNG, WebP, HEIC. Reject RAW.
- Cloudflare R2 over the plain S3 API, presigned PUT from the browser. No MinIO, no
  Cloudinary.
- Photo rows store a provider-agnostic `storage_key`, never a vendor URL.
- Originals are not kept.

## Left alone

- Table naming stays as it is. If the schema outgrows one flat list, use Postgres
  schemas grouped by domain, not name prefixes.
